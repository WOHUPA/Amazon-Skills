# 5 维映射参考：阶段 0 采集完后，如何落到 SKILL.md

这份文档是 `wohu-amazon-skill-creator` 的**内部参考材料**，不是给用户填写的大表单。实际内容按 5 维使用。

用途：
- 帮 Codex 把阶段 0 收集到的 5 维答案映射到 `SKILL.md`
- 作为生成初稿时的字段提取参考
- 提供一个卖家场景示例，方便校验答案粒度够不够

不要把这份文档整段发给用户填写。阶段 0 的正式问法以 `references/5步引导流程.md` 为准。

---

## 第一部分：5 维到 SKILL.md 的映射

| 阶段 0 维度 | 进入 SKILL.md 的哪里 | 提取重点 |
|------------|----------------------|----------|
| Q1 现有做法 | `## 当前工作流（人工版）` | 当前做法、耗时、痛点、已有工具 |
| Q2 具体步骤 | `## Skill 工作流（自动版）` | 步骤顺序、输入、输出、判断条件；报告型 Skill 追加来源表、指标字典和五级字段 |
| Q3 方法论 | `## 核心原则 / 踩坑规避` | 阈值、优先级、例外条件、禁忌 |
| Q4 调用方式 | YAML `description` + `## 触发场景` | 触发方式、真实话术、业务入口 |
| Q5 期望输出 | `## 输出规范` | 产物类型、保存位置、命名规则、完成信号；报告型 Skill 追加版本路由和完整增强清单 |

业务背景不单独提问，由用户原始需求、当前工作流和痛点归纳生成。

---

## 第二部分：字段提取提示

### Q1 现有做法

至少提取出：
- 当前是纯手动、半自动还是全新流程
- 现在已经在用什么工具
- 一次做多久、最烦哪一步
- 用户原始需求里暴露的业务场景和损失

适合写进：
- `## 当前工作流（人工版）`
- `## 业务背景`

### Q2 具体步骤

每一步尽量提取：
- 动作
- 输入
- 输出
- 判断

如果流程使用 MCP，还要提取：

- `mcp_selection_mode=advisory|user_fixed|auto_route`
- 具体 Skill 场景、目标站点、对象范围和必需字段
- 推荐首选、独立校验源、同站点条件兜底及其证据快照
- 用户覆盖规则、切换触发、禁止切换的错误状态和停止条件

按 `references/mcp-selection.md` 给出建议，不把平台总榜或工具数量变成强制默认源。用户指定来源通过硬门时保留其偏好；站点回落、语义无效、私有事实来源或安全错误不能被偏好覆盖。

如果用户只给动作顺序，没有判断逻辑，不要直接写入 `SKILL.md`，先回到阶段 0 补问。

如果目标产物是分析、诊断、监控或运营报告，还要提取：

- 基础来源与增强来源，以及各自的粒度、口径、时效、追溯和降级边界
- 指标定义/公式、单位/币种、来源、有效范围、缺失行为和依赖动作
- `basic_required`、`enhancement_global_required`、`module_required`、`full_required`、`display_optional`

适合写进：
- `## Skill 工作流（自动版）`
- 如步骤太长，可把细节拆到 `references/` 再在正文里指路

### Q3 方法论

重点提取：
- 具体阈值
- 趋势/对比口径
- 优先级规则
- 例外排除条件

亚马逊卖家常见信号：
- `BCG 健康阈值`
- `广告占比异常`
- `新品期不纳入稳定判断`
- `节假日周单独处理`

适合写进：
- `## 核心原则 / 踩坑规避`

### Q4 调用方式

重点提取：
- 默认触发方式：一句话 / 先问参数 / 上传文件
- 最常见的业务入口：Sorftime、领星、SIF、本地表格、飞书等
- 2-3 句真实触发话术

适合写进：
- YAML `description`
- `## 触发场景`

### Q5 期望输出

重点提取：
- 产物类型
- 输出落点
- 命名规则
- 完成信号

报告型 Skill 还要提取：

- 基础版包含什么，以及基础必填缺失时如何阻断
- 增强模块及各模块最小有效指标
- 完整增强清单和不参与判定的展示型选填字段
- `auto|basic|enhanced` 的入口、版本标签、降级原因和模块 `SKIP/MANUAL` 规则

适合写进：
- `## 输出规范`

## 第三部分：卖家场景示例

**场景**：卖家每周都要做一次 BCG ASIN 的关键词自然排名检查，现在想把这个流程做成 skill。

### Q1 现有做法

- 每周一早上手动做
- 打开 Sorftime，搜 BCG 这个 ASIN，看每个核心词的排名位置
- 把结果复制到 Excel，和上周数据做对比
- 每个 ASIN 约 15 分钟，12 个 ASIN 一共要 3 小时
- 最烦的是复制和对比，经常因为嫌麻烦跳过
- 可归纳出的背景：自然流量是免费流量，排名掉了要拿广告钱补，一周没发现可能损失广告费和销量

### Q2 具体步骤

- 第 1 步：从 Sorftime 拉 BCG 的核心 ASIN 关键词数据
- 第 2 步：过滤出核心词清单
- 第 3 步：对比上一周记录；如果没有上周数据，就先记当前周基线
- 第 4 步：标记排名变化 > 10 位的异常词；如果掉出前 20 名，升级为严重
- 第 5 步：生成 Markdown 报告并保存到固定目录，同时把摘要发到飞书运营群
- 基础来源：Sorftime 当前关键词排名；增强来源：本地可比上周记录和 SIF 排名诊断，必须声明同一站点、ASIN、关键词和周周期
- 基础指标：当前自然排名 `basic_required`；历史排名和排名变化属于趋势模块 `module_required`；SIF 诊断属于市场校验模块 `full_required`；备注文本属于 `display_optional`

### Q3 方法论

- 排名变化 < 5 位不算异常
- 新品上架 < 30 天不纳入稳定判断
- 节假日周单独处理，不和普通周硬比
- 同一个核心词连续 2 周下滑，必须升级人工介入

### Q4 调用方式

- 触发方式：一句话直接触发
- 业务入口：Sorftime 研究 + SIF 排名诊断
- 真实话术：
  - “帮我查一下 BCG 这周的关键词排名”
  - “跑一下每周的关键词排名检查”
  - “看下哪些词掉出前 20 了”

### Q5 期望输出

- 产物类型：Markdown 报告 + 飞书消息 + 异常清单
- 落点：本地目录 + 飞书群
- 命名规则：`YYYY-MM-DD_BCG_关键词自然排名周报.md`
- 完成信号：终端回一句“已完成，异常 N 个、严重 M 个，报告已发到飞书”
- 基础版：只有当前排名时输出当前快照并说明缺少趋势增强
- 部分增强：历史趋势或 SIF 校验任一模块完成
- 完整增强：趋势模块和 SIF 校验模块均完成；备注缺失不影响完整增强
- 默认 `auto`；增强口径冲突时保留基础版，显式 `enhanced` 才阻断

## 第四部分：生成时的自检清单

开始写 `SKILL.md` 前，快速对照：

- `业务背景` 是否能从用户原始需求、现有做法和痛点里归纳出来
- `当前工作流（人工版）` 里是否有真实人工基线，不是空壳
- `Skill 工作流（自动版）` 里是否能看出判断逻辑
- 使用 MCP 时是否给出可覆盖的推荐路由，而不是强制默认源；是否记录精确站点、必需字段、证据快照、切换和停止条件
- `核心原则 / 踩坑规避` 是否至少有一条具体规则
- `触发场景` 是否写入真实话术，而不是抽象标签
- `输出规范` 是否同时写明产物形式和落点
- 报告型 Skill 是否有来源表、指标字典、五级字段、三种版本标签、完整增强清单和缺失行为
- 非报告型 Skill 是否明确跳过报告版本问诊，避免无关约束

如果以上任一项回答不上来，不要硬写，先回阶段 0 补采集。
