# MCP 数据源选择方法

本文件只在目标 Skill 未来需要调用 MCP 时读取。它用于给出有证据、可覆盖的推荐，不替用户强制指定供应商，也不要求创建 Skill 时立刻调用真实 MCP。

## 1. 证据来源与使用边界

当前建议基线来自用户提供的《MCP测评方法》和《MCP测评仪表盘》：

- 方法版本：`1.6.0`
- 快照日期：`2026-08-07`
- 运行批次：`MCP-ALL-MARKETPLACES-20260807-01`
- 范围：六家直连数据型 MCP 的公开只读夹具，以及 LinkFox OS 独立编排赛道
- 来源层级：`S4` 第三方公开市场数据
- 最高证据：本轮保守按 `E3` 真实 MCP 调用；没有 Seller Central、Amazon Ads、官方 ABA 或其他 `E5` 外部真值校准

因此，这份快照可以支撑“当前场景候选、字段路由和带限制的推荐”，不能支撑“某家数据最准”“某家全站点通用”或“综合总冠军”。目标 Skill 每次实际运行前仍要检查当前工具、Schema、授权、站点、字段和数据新鲜度。

## 2. 推荐模式

目标 Skill 需要 MCP 时，记录 `mcp_selection_mode`：

| 模式 | 适用场景 | 创建器行为 |
| --- | --- | --- |
| `advisory` | 默认；用户没有锁定供应商 | 给出首选、独立校验源、条件兜底和理由，并明确“可由用户改选” |
| `user_fixed` | 用户明确指定 MCP | 保留用户选择，但仍检查安全、来源、站点、语义和必需字段硬门；不合格时说明阻断并给替代建议 |
| `auto_route` | 用户明确要求目标 Skill 运行时自动选源 | 生成可审计路由卡、切换条件和停止条件；只在合格候选集中自动切换 |

推荐本身是软规则。用户偏好、已授权工具、额度、成本或现有技术栈可以改变首选；安全、隐私、来源资格、请求/返回站点一致性和必需字段语义是硬门，不能被偏好覆盖。

## 3. 先定义场景合同

不要先问“哪家 MCP 分最高”。先从用户需求推导以下合同，只补问会改变来源资格或业务口径的高影响信息：

| 字段 | 最低要求 |
| --- | --- |
| `skill_scenario` | 具体到“US 评论原文 VOC”，不能只写“选品” |
| `business_question` | 本次必须回答的问题 |
| `marketplace` | 精确站点；多站点逐站判断 |
| `object_scope` | ASIN、父体/子体、关键词、类目节点、评论或其他对象 |
| `required_fields` | 缺失即不能完成产物的字段集合 |
| `time_unit_scope` | 时间粒度、单位、币种、时区、归因和 `dataAsOf` 要求 |
| `minimum_evidence` | 本场景最低 E 级和站点证据阶段 |
| `source_requirement` | `OFFICIAL_FACT_REQUIRED`、`PUBLIC_MARKET_ALLOWED` 或 `ENRICHMENT_ONLY` |
| `privacy_write_boundary` | 可外发字段、只读/写操作和人工确认点 |
| `runtime_budget` | 可选的延迟、额度、成本、重试和新鲜度边界 |

合同不完整时可以给候选建议，但状态只能是 `ROUTE_UNTESTED` 或 `MANUAL_REVIEW`，不能生成自动主路由。

## 4. 来源优先级与资格门

按顺序检查，前一步失败即停止，不用后面的低成本或低延迟抵消：

1. **安全与授权**：凭证、隐私、跨账号、未经确认的写操作或越权触发时立即阻断。
2. **事实来源**：店铺、广告、订单、库存、财务、结算和真实经营结果，以官方 API、已授权第一方 MCP/ERP、团队可信服务或官方导出为事实主源；第三方 MCP 只做公开市场增强。
3. **当前可发现性**：确认本次 Codex 环境能发现目标 MCP 和工具。快照中出现但当前不可发现的来源只列为“待安装/待确认候选”，不编造工具名或回包。
4. **精确站点**：候选工具必须在请求站点有对应工具级证据；不得从厂商级站点并集、其他工具或 US 成功结果外推。
5. **能力与 Schema**：必需能力、输入参数和返回字段有当前工具绑定；只有目录或营销说明不能进入自动候选集。
6. **语义与贡献**：请求与返回站点、对象、父子体、单位、时间和字段语义一致，且返回了本场景必需字段。HTTP 200、空壳对象或占位值不等于可用。
7. **场景产物**：候选来源能形成目标 Skill 的完整必需产物，并保留证据回链、缺失字段和人工门。
8. **运行约束**：新鲜度、稳定性、限流、延迟、额度和成本满足目标 Skill 的预算。
9. **主备与停止**：写清首选、独立校验源、同站点条件兜底、切换触发和禁止切换的错误状态。

多个候选都合格时依次比较：场景就绪度 → 同站点语义、字段、失败处理和稳定性 → 测试完整度与证据等级 → 新鲜度 → 延迟 → 成本。只在前一项并列时比较后一项，不生成隐藏的综合分。

## 5. 当前场景推荐快照

以下内容是 `2026-08-07` 快照的建议起点，不是永久默认值。`首选` 仅在目标站点、目标工具和必需字段继续通过资格门时成立。

| Skill 场景 | 当前首选 | 补充或兜底 | 快照状态与边界 |
| --- | --- | --- | --- |
| ASIN 基础事实与竞品卡 | 卖家精灵 | 西柚 → Sorftime → SIF；极目只补基础字段 | `ROUTE_CONDITIONAL`；完整路由证据为 US；关键字段为空才换源，价格冲突回查 Amazon/官方事实，禁止平均 |
| 关键词需求与竞争研究 | 按站点选，卖家精灵优先 | Sorftime、SIF、西柚、飞鱼、极目按字段进入 | `ROUTE_CONDITIONAL`；周量、月量、ABA、CPC、排名和时间粒度分别路由，不混算 |
| Amazon 类目节点与市场结构 | 卖家精灵 | 无整套自动备份 | `ROUTE_CONDITIONAL`；本轮只有卖家精灵贡献 Amazon browse node；vendor taxonomy 不可替代 |
| 评论原文与 VOC | Sorftime | 卖家精灵评论原文 | `ROUTE_READY`（冻结的 US 场景内）；必须保留评论原文、样本范围和父子体边界，VOC 主题回链原文 |
| ASIN 流量词与排名 | 卖家精灵 | SIF、Sorftime、西柚、极目按字段替补 | `ROUTE_CONDITIONAL`；自然位、广告位、ABA 排名、趋势和 `trafficScore` 不可互换 |
| 跨字段选品/经营判断 | 卖家精灵打底 | 其余五家按字段补证 | `MANUAL_REVIEW`；不同来源估算不平均，缺同一 `dataAsOf`、Amazon node 或原始 VOC 时只输出带缺口证据包 |
| 细分市场机会与主题证据 | 极目 | 飞鱼仅在 US 补评论主题 | `ROUTE_CONDITIONAL`；极目当前限 US/DE/JP，`nicheId` 不能当 Amazon browse node，主题不能替代 ASIN 评论原文 |

`ROUTE_READY` 只表示在冻结场景与版本内可路由，不表示外部准确率冠军。LinkFox OS 是异步路由、组合和恢复的编排层，不作为第七家独立原始数据源；使用时必须披露底层 `providerFamily`，同源直连与编排只算一个证据家族。

## 6. 关键词场景的站点建议

仪表盘对关键词代表端点给出了更细的站点边界。它们不能继承给同厂商未测工具：

| 站点 | 当前建议 |
| --- | --- |
| US | 卖家精灵、Sorftime、SIF、西柚按字段构成主备；飞鱼补关键词证据，极目只补商品发现 |
| DE / JP | 卖家精灵、Sorftime、SIF、西柚按字段构成主备；极目只补商品发现 |
| UK / FR / IT / ES / CA / BR | 卖家精灵、Sorftime、SIF、西柚代表端点已通过；UK/GB 参数按工具原生枚举 |
| MX | 卖家精灵优先；Sorftime、西柚作备份；SIF 仅作低置信度补充，不单独承担趋势结论 |
| AU / AE / SA | 卖家精灵、Sorftime、SIF、西柚代表端点已通过，仍按必需字段选择 |
| IN | 当前仅卖家精灵代表端点通过；Sorftime 待核验，SIF 因静默回落 US 必须阻断，西柚、飞鱼、极目不进入候选 |
| TR | 当前仅卖家精灵代表端点通过；其他来源为参数阻断、语义阻断或明确不支持 |
| BE / NL / PL / SE / SG | 当前无自动路由；进入测试或人工配置 |
| EG / IE / ZA | 当前无自动路由；进入测试或人工配置 |

飞鱼 `profile_keyword` 的当前代表端点只在 US 可用。极目代表链路当前只在 US、DE、JP 可用。SIF 关键词需求在 MX 只能低置信度补充，在 IN 因站点语义错误不得使用。任何运行时新证据都要限定到 `provider × tool × reportType × marketplace × objectScope`。

## 7. 推荐输出格式

创建器给出建议时，使用一个简短路由卡，不要求用户填写整份测评合同：

```yaml
mcp_selection_mode: advisory
snapshot_at: 2026-08-07
route_status: ROUTE_CONDITIONAL
scenario: US ASIN traffic ranking
primary:
  provider: sellersprite
  reason: 同站点、目标字段和场景证据满足当前候选门
validation_source: null
fallbacks:
  - provider: sif
    trigger: 主源超时或必需字段缺失，且同站点字段合同有效
stop_conditions:
  - 请求与返回站点不一致
  - 排名类型或时间粒度不可比
user_override: allowed_if_eligible
```

面向用户的说明至少包含：推荐来源、为什么推荐、适用站点/字段、快照日期、已知限制、用户能否改选、切换条件和停止条件。用户未要求自动路由时，不要把建议静默写成强制依赖。

## 8. 用户覆盖与失败处理

- 用户指定的来源通过硬门时，按 `user_fixed` 使用；可以同时提示测评中的更优候选，但不强制改选。
- 用户指定来源尚未测过时，标 `ROUTE_UNTESTED`，允许作为人工配置或待验证候选，不把它升级为已验证主源。
- 用户指定来源触发安全、私有事实来源、站点回落、语义无效或必需字段缺失时，不能按偏好继续执行；说明具体阻断原因并推荐合格候选。
- 超时、限流、明确不支持或合同声明的终端错误，才允许切到同站点合格备用源。
- 站点不一致、单位不一致、官方事实冲突、语义冲突和安全错误不得靠“换一家继续跑”掩盖，进入 `MANUAL_REVIEW`、`NO_ROUTE` 或 `SECURITY_BLOCKED`。
- 多源结果冲突时并列保留，不平均、不多数表决；高错误成本结论转人工确认。

## 9. 正反例

**正例：用户没有指定来源**

> “创建一个美国站评论 VOC Skill，MCP 你给我建议，但不要强制。”

输出 `advisory` 建议：Sorftime 评论原文为首选、卖家精灵为独立备用；说明快照日期、US 范围、原文与父子体门槛，并允许用户改选。

**正例：用户指定了合格来源**

> “我已经有卖家精灵授权，这个 US ASIN 卡就用它。”

记录 `user_fixed`，验证当前工具和字段后使用卖家精灵；可提示其他兜底，但不强制更换。

**反例：偏好试图绕过语义门**

> “印度站关键词永远用 SIF，只要 HTTP 200 就算成功。”

不得照做。当前快照中 SIF 的 IN 代表端点出现静默 US 回落，属于语义无效；建议改用同站点已验证候选或进入人工配置。HTTP 成功不能替代站点和字段语义验证。

**反例：用榜单替代场景合同**

> “直接选工具最多的那家，所有站点都用同一个 MCP。”

不得生成全局默认源。先锁定场景、站点和必需字段；没有对应工具级证据时输出 `ROUTE_UNTESTED`。

## 10. 复测与过期条件

以下任一变化都使相关建议过期并触发局部复核：

- 工具名称、数量、参数、返回字段或 `schemaHash` 变化；
- 认证、配额、计费、缓存、限流或可用状态变化；
- 站点枚举、请求/返回站点、指标定义、单位、时间粒度或刷新频率变化；
- 新增 provider adapter、字段转换或 `providerFamily` 映射；
- 关键字段缺失、语义异常、数据漂移、决策翻转或 P0/P1 事件；
- 目标 Skill 的业务产物、必需字段、人工门或风险级别变化；
- 到达目标 Skill 自己声明的复核周期。

创建 Skill 时记录 `snapshot_at`、证据范围和复测触发器。当前环境只确认工具可发现或 Schema 可见时，最多给候选建议，不把历史仪表盘快照冒充实时可用性。
