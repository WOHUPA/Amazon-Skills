# Golden Set

本文件是 `wohu-amazon-skill-creator` 的人工回归基准。结构化版本位于 `evals/evals.json`，这里保留便于审查的中文案例说明。

通过标准：每次修改触发描述、任务分流、评测规则、创建质量门或 MCP 指引后，至少复核全部案例；正例必须进入对应流程，负例不得触发本 skill 或必须明确转交更合适的业务 skill。

## 案例 1：完整创建新 Skill

用户提示：

```text
我想做一个专门检查 Listing 差评机会点的 skill，你用 wohu-amazon-skill-creator 帮我一步步梳理。
```

期望结果：

- 识别为新建 skill，而不是直接做一次 Listing 分析。
- 按 Q1 到 Q5 顺序推进，至少先询问现有做法。
- 说明输出会映射到 `SKILL.md` 的主结构。

## 案例 2：快速试验例外

用户提示：

```text
先快速试试，帮我把广告搜索词浪费词识别流程做成 skill，先别问太多。
```

期望结果：

- 识别用户明确要求快速试验。
- 只聚焦 Q2 和 Q5，不一次性丢出完整模板。
- 提示快速版本可能偏空，需要后续补齐 Q1、Q3、Q4。

## 案例 3：优化已有 Skill

用户提示：

```text
这是一个现有 skill 的目录，请你优化它，不要重新从 5 步问起：C:/work/skills/amazon-review-miner
```

期望结果：

- 识别为优化已有 skill。
- 不强迫用户重新回答 5 步问题。
- 计划覆盖触发描述、流程可执行性、上下文体积、工具依赖、跨平台兼容和验证方式。

## 案例 4：只审查不编辑

用户提示：

```text
帮我审查这个 skill 哪里容易误触发，只要 review，不要改文件。
```

期望结果：

- 识别为只审查，不编辑。
- 先输出问题和风险，而不是直接套 5 步创建流程。
- 不会在用户未授权时修改文件。

## 案例 5：一次性业务分析负例

用户提示：

```text
帮我分析这个 ASIN 的竞品关键词机会，直接给结论。
```

期望结果：

- 不把一次性竞品或关键词分析误判为 skill 创建任务。
- 如果回应，应说明本 skill 只在用户要沉淀流程时使用。
- 不询问 5 步创建问题。

## 案例 6：普通代码任务负例

用户提示：

```text
帮我写一个 React 表格组件，支持分页和筛选。
```

期望结果：

- 不把普通代码实现误判为创建 skill。
- 不读取亚马逊业务模板。
- 不询问 MCP 或运营流程问题。

## 案例 7：MCP 设计但不现场查询

用户提示：

```text
把用 SIF 和 SellerSprite 查竞品流量再生成周报的流程做成 skill。
```

期望结果：

- 读取或引用对应 MCP 集成指南的使用边界。
- 把 MCP 工具作为新 skill 的未来数据来源设计。
- 明确默认不现场调用 MCP 查询。

## 案例 8：补齐评测与验收

用户提示：

```text
帮我给刚写好的亚马逊库存预警 skill 加测试用例和验收标准。
```

期望结果：

- 覆盖正常触发、参数缺失和边界场景。
- 输出可验证断言，而不是只有主观描述。
- 建议把新增案例沉淀到 `evals/evals.json`。

## 案例 9：审查体检必须完整报告

用户提示：

```text
帮我给这个亚马逊广告 skill 做体检，只要诊断报告，先不要改文件。
```

期望结果：

- 识别为审查 / 体检已有 skill，而不是新建 skill。
- 输出完整诊断报告，不能只给总分、评级或几条泛泛建议。
- 报告包含结论摘要、证据清单、风险排序、ROI 修复清单、待确认执行计划、验证与未运行项。
- 在用户确认前不修改文件，并说明只读取任务必要文件，不暴露密钥、token 或客户敏感信息。

## 案例 10：输入质量不足时只出草案

用户提示：

```text
帮我做一个亚马逊自动化 skill，能把运营都自动处理掉，具体流程你自己想。
```

期望结果：

- 标注数据质量等级为 C 或 D，而不是直接生成完整可执行 skill。
- 说明缺少稳定任务、输入输出、边界、工具和验证方式。
- 只给候选方向或补问清单，不创建外部写操作或自动化执行承诺。

## 案例 11：创建完成交付必须包含完整契约

用户提示：

```text
我已经回答完 5 个问题了，请你生成这个库存预警 skill 的交付说明。
```

期望结果：

- 交付包含 Skill 名称、路径、触发场景、不适用场景、输入要求、输出产物、目录结构和核心执行流程。
- 交付包含已运行验证、未验证内容与风险、后续迭代点。
- 至少给出一个正例、一个反例和一个最小执行验证。

## 案例 12：优化计划必须绑定证据链和子 agent 边界

用户提示：

```text
帮我优化这个 skill，并让子 agent 一起改快一点。
```

期望结果：

- 先读取目标 skill 并输出数据质量等级和证据等级。
- 每个计划项都包含问题、证据等级、改动对象、动作、验收方式和风险。
- 未获用户明确确认前不调用 `spawn_agent`；即使用户提到子 agent，也要先判断当前会话可用性、任务边界和是否建议取消启动。

## 案例 13：报告型 Skill 先定义来源与指标

用户提示：

```text
帮我创建一个亚马逊库存健康周报 skill，数据可以从 ERP 和本地库存表获取。
```

期望结果：

- 识别目标产物是运营报告，读取报告分级契约；不直接从工具名猜报告版本。
- 先从现有信息推导数据来源表和指标字典，只补问无法确认的高影响口径。
- 来源表包含基础/增强角色、来源类型、粒度、口径、时效、追溯和降级边界；指标归入五级字段。
- 不要求用户一次性填写完整模板，也不为了设计 Skill 现场查询真实店铺数据。

## 案例 14：部分增强与完整增强按模块判定

用户提示：

```text
这个库存报告基础数据一定有；利润模块有时能取到，补货和退货模块不一定齐。不要因为少一个字段整份退回基础版。
```

期望结果：

- 设计 `基础版报告`、`增强版报告（部分增强）`、`增强版报告（完整增强）` 三种固定标签。
- 至少一个模块的 `module_required` 完成时生成部分增强，缺失模块只标 `SKIP/MANUAL`。
- 所有预先声明的 `full_required` 模块完成时才生成完整增强；`display_optional` 缺失不影响完整增强。
- 报告版本、数据质量和证据等级保持为三条独立轴。

## 案例 15：自动保底、安全阻断与非报告边界

用户提示：

```text
给报告 skill 默认自动判断版本：增强来源口径不一致时也要保留基础报告；但如果我强制增强就报错。普通 Listing 文案 skill 不要问这些版本问题。
```

期望结果：

- `auto` 在增强全局口径无效或零模块完成时生成带原因的基础版，显式 `enhanced` 阻断。
- 基础必填缺失时只输出数据缺口，不生成空壳报告；凭证、损坏数据或非法状态在任何模式下阻断。
- 非报告型 Skill 明确跳过来源/指标和报告版本问诊。
- 涉及确定性取数、计算或多模块路由时，要求目标 Skill 生成专用脚本和对应测试，不建立共享运行时。

## 案例 16：MCP 未锁定来源时给出非强制建议

用户提示：

```text
创建一个美国站评论 VOC skill，MCP 你根据测评给我建议，但不要强制替我决定。
```

期望结果：

- 记录 `mcp_selection_mode=advisory`，明确推荐可由用户改选。
- 建议限定在 US 评论原文/VOC 场景，给出 Sorftime 首选、卖家精灵独立备用，以及原文回链、父子体和样本范围门槛。
- 标注 2026-08-07 快照和 S4/E3 边界，不宣称外部准确率或全局冠军。
- 创建阶段只设计未来路由；除非用户要求现场验证，不调用真实 MCP。

## 案例 17：MCP 用户偏好不能绕过语义硬门

用户提示：

```text
给我创建一个印度站关键词 skill，永远固定用 SIF，只要 HTTP 200 就算成功。
```

期望结果：

- 保留用户偏好记录，但不跳过请求/返回站点一致性和必需字段语义检查。
- 明确 HTTP 200 不等于业务语义有效；当前快照中 SIF 的 IN 代表端点静默回落 US，必须退出自动候选集。
- 建议同站点已验证候选；没有合格来源时标 `ROUTE_UNTESTED`、`MANUAL_REVIEW` 或 `NO_ROUTE`。
- 不用其他站点成功结果、平台总榜或工具数量替代 IN 工具级证据。
