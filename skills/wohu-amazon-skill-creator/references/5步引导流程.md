# 5 步引导式流程

本文件是 `wohu-amazon-skill-creator` 新建 skill 时的阶段 0 执行脚本。新建 skill 时按 5 步推进。优化或审查已有 skill 时，不强制从 5 步重新问起，应先读取现有文件并诊断问题。

## 使用方式

- 顺序推进 Q1 到 Q5，一个主题合格后再进入下一个。
- 优先用选项题降低用户表达成本；如果 Codex 当前没有结构化问答工具，就直接用普通编号列表提问。
- 每题结束做通关条件检查：答案为空、敷衍、矛盾、无输入输出、无判断规则时，当场追问。
- 不把整份模板一次性发给用户填写。
- 用户明确说“先快速试试”时，只问 Q2、Q5，并标记 Q1、Q3、Q4 待补。
- 每轮收集后标注数据质量等级 A/B/C/D；B/C/D 必须说明限制、待补信息和未验证项。

## 创建前质量门

开始写 `SKILL.md` 前，先判断这个需求是否真的适合沉淀成 skill：

| 数据质量等级 | 判定 | 动作 |
| --- | --- | --- |
| A | 流程重复、输入输出清楚、边界和验证方式明确 | 直接进入 5 步通关和目录规划 |
| B | 可创建，但缺少部分真实案例、工具验证或边界细节 | 继续创建，并在交付中标注限制和待补项 |
| C | 只有方向或方法论，缺少稳定输入输出 | 只生成 skill 草案或方法论文档，不声称可稳定执行 |
| D | 一次性任务、边界不清、工具不可用或有高风险未确认 | 暂停创建，先补案例、权限、边界或工具可用性 |

质量门检查 7 项：任务稳定性、输入完整性、输出明确性、边界清晰度、工具可用性、安全可控性、验证可行性。

若涉及外部写操作、批量修改、账号权限、token、cookie、个人隐私或商业敏感数据，必须先确认范围、预览方式和回滚边界；未确认时只写只读流程或草案。

## Q1 现有做法

询问当前状态：

1. 纯手动：Excel、复制粘贴、肉眼判断。
2. 工具串联：Sorftime、SIF、SellerSprite、领星、ERP、飞书等需要人工搬数据。
3. 半自动：已有脚本、表格公式、n8n、宏，但需要人工触发。
4. 全新流程：以前没系统做过。

追问：

> 现在做一次大概花多久？最容易出错或最容易拖延的是哪一步？

通关条件：非全新流程必须有耗时或痛点；不能只说“有 Excel”。业务背景从用户原始需求、当前做法和痛点里归纳，不单独设置“业务目标”提问。

## Q2 具体步骤

先根据用户原话和 Q1 现有做法判断是否读取对应业务模板：

- 选品开发：`references/业务流程模板/选品开发流程.md`
- 关键词广告：`references/业务流程模板/关键词广告流程.md`
- Listing 优化：`references/业务流程模板/Listing优化流程.md`
- 日常运营监控：`references/业务流程模板/日常运营监控流程.md`

再确认数据来源，可多选：

1. Sorftime MCP
2. SIF MCP
3. SellerSprite MCP
4. 本地 Excel / CSV / TXT
5. 飞书表格 / 飞书消息
6. 人工粘贴文本
7. 其他数据源

用户选择或流程推导出 MCP 时，读取 `references/mcp-selection.md`，并确认选源模式：

1. `advisory`：默认，由创建器给出首选、独立校验源和条件兜底，用户可改选。
2. `user_fixed`：用户已指定来源；保留偏好，但仍检查安全、来源、站点、语义和必需字段硬门。
3. `auto_route`：用户明确要求目标 Skill 运行时自动选源；必须写路由卡、切换条件、停止条件和审计字段。

先从业务场景、站点、对象、必需字段、时间/单位、数据新鲜度和来源类型推导候选，不因仪表盘总分、工具数量或品牌印象强制选源。创建阶段默认只设计未来路由；除非用户要求现场验证，不调用真实 MCP。

如果目标 Skill 最终产出分析、诊断、监控或运营报告，立即读取 `references/report-editions.md`。不要只记录工具名；先从用户资料、现有文件列名、接口文档和业务模板推导数据来源表与指标字典，再补问无法确认的高影响信息。

报告型 Skill 的 Q2 额外通关条件：

- 数据来源表已区分基础来源和增强来源，并写明来源类型、粒度、口径、时效、追溯、主来源和允许的降级来源。
- 指标字典已写明定义/公式、单位/币种、粒度、来源、有效范围、缺失行为和依赖动作。
- 每个指标已归入 `basic_required`、`enhancement_global_required`、`module_required`、`full_required` 或 `display_optional`。
- 私有店铺数据没有使用公开网页或第三方市场数据作为替代来源。
- 使用 MCP 时已记录 `mcp_selection_mode`、推荐理由、快照日期、用户覆盖规则、同站点兜底和停止条件；未测或不合格来源没有被写成自动主源。

让用户按下面格式描述 3-8 步：

```text
第 X 步：[动作]
  输入：[来自哪里，文件路径 / MCP 工具 / 上一步输出]
  输出：[产出什么，放到哪里]
  判断：[如果 xxx 则 yyy，否则 zzz；没有判断写“无”]
```

通关条件：至少 3 步；每步能看出输入和输出；如果用户选择非线性流程，必须有至少一个判断分支。

## Q3 方法论

先读取 `references/行业指标标准/亚马逊运营指标手册.md`，再让用户选择判断框架：

1. 阈值判断：超过或低于某个值就预警。
2. 趋势对比：对比上周、上月、历史均值或类目均值。
3. 优先级排序：异常很多时按轻重缓急处理。
4. 异常归因：不仅报异常，还判断可能原因。
5. 例外排除：新品期、节假日、促销周、断货恢复期单独处理。
6. 用户自定义规则。

追问：

> 挑最关键的 1-3 条规则，最好写成“如果……则……”或“超过/低于多少算异常”。

通关条件：至少有一条具体规则，不能只有“看经验”“综合判断”。

## Q4 调用方式

询问触发方式：

1. 一句话直接触发。
2. 先问参数再执行。
3. 上传文件后自动识别。
4. 定期巡检或自动化任务触发。

询问真实话术：

> 给 2-3 句你平时真的会说的话，不要写成说明书。

示例：

- “帮我跑一下这周核心词排名”
- “用 Sorftime 和 SellerSprite 做个选品可行性分析”
- “我把 CSV 丢给你，按日常运营监控流程出日报”

通关条件：必须有触发方式和至少 2 句真实话术。

## Q5 期望输出

询问产物类型，可多选：

1. Markdown 报告
2. 表格 / CSV
3. 异常清单
4. 行动建议
5. 飞书消息
6. 改写后的文案或模板

询问落点：

1. 当前对话直接展示
2. 本地目录
3. 飞书
4. 表格或数据文件

追问：

> 文件怎么命名，或做完后你希望我怎么告诉你“已经完成”？

如果产物包含分析、诊断、监控或运营报告，再锁定以下内容：

1. 基础版必须具备哪些来源和指标，缺失时是否阻断。
2. 有哪些增强模块，每个模块的最小有效指标是什么。
3. 哪些模块和指标进入完整增强清单；纯展示字段归入 `display_optional`。
4. 默认是否使用 `report_edition=auto`，以及显式 `basic` / `enhanced` 的入口形式。
5. 报告头如何展示版本原因、来源、指标口径、模块覆盖、数据质量和证据等级。

报告型 Skill 的默认答案固定为：`auto` 在增强全局口径无效或零模块完成时保留基础版；至少一个模块完成时生成部分增强；完整增强清单全部完成时生成完整增强；显式 `enhanced` 对全局缺口阻断；凭证或损坏数据在任何模式下阻断。

通关条件：必须同时知道产物形式和落点，且有命名规则或完成信号。报告型 Skill 还必须锁定基础范围、增强模块、完整增强清单和缺失行为。

## 总通关条件清单

进入写 `SKILL.md` 前确认：

- 已给出数据质量等级 A/B/C/D；B/C/D 的限制和待补信息已经写入草案或交付说明。
- Q1 有现有做法、工具、耗时或痛点。
- Q2 有步骤、输入、输出和必要判断。
- 报告型 Skill 的 Q2 已有数据来源表、指标字典和五级字段；非报告型 Skill 已明确跳过该契约。
- 使用 MCP 时，Q2 已按选源方法给出建议或记录用户固定来源，并通过安全、来源、站点、语义和必需字段资格门。
- Q3 有至少一条具体规则。
- Q4 有真实触发话术。
- Q5 有产物形式和落点。
- 报告型 Skill 的 Q5 已有基础版、部分增强、完整增强、`auto` 保底、显式增强阻断和安全错误规则。
- 已判断是否需要 `references/`、`scripts/`、`assets/`、`agents/openai.yaml`，且没有创建与执行路径无关的资源。
- 已准备至少一个正例、一个反例和一个最小执行验证。

任一项不达标，回到对应问题补问。
