# 报告型 Skill 分级契约

本文件只适用于最终产出分析、诊断、监控或运营报告的 Skill。文案改写、图片生成、格式转换、单纯数据导出等非报告型 Skill 不强制使用基础版/增强版。

## 1. 先定义事实，再定义版本

报告版本不能按“是否安装 MCP”或“字段数量多少”猜测。创建或优化报告型 Skill 时，先建立数据来源表和指标字典，再决定基础版、部分增强和完整增强。

### 数据来源表

至少包含以下列：

| 字段 | 含义 |
|:---|:---|
| `source_id` | Skill 内稳定、唯一的来源标识 |
| 来源角色 | `basic` 或 `enhancement` |
| 来源类型 | `first_party_private`、`official_public`、`third_party` 或 `manual` |
| 提供方与入口 | MCP、API、ERP、可信服务、官方导出文件或人工输入 |
| 数据粒度 | 店铺、账号、活动、ASIN、SKU、关键词、订单等 |
| 口径范围 | 站点、实体、起止日期、币种、时区、归因、税口径及其他领域口径 |
| 时效要求 | 实时、日、周、月或自定义 SLA |
| 来源追溯 | 工具、接口或文件名，读取状态与读取时间；不得包含凭证 |
| 主来源与降级 | 主来源失败时允许使用什么；禁止用什么替代 |

一个指标只能有一个当前生效主来源。允许降级时必须声明优先级和口径差异；不得把冲突来源求平均或静默拼接。

### 指标字典

至少包含以下列：

| 字段 | 含义 |
|:---|:---|
| `metric_id` | Skill 内稳定、唯一的指标标识 |
| 指标名称 | 报告中的展示名称 |
| 定义或公式 | 原始字段或可审计计算公式；派生指标写清分子和分母 |
| 单位与币种 | 数量、百分比、天数、ISO 币种等 |
| 数据粒度 | 必须与来源粒度兼容 |
| `source_id` | 对应数据来源表中的来源 |
| 字段等级 | 五级字段中的一种 |
| 有效范围 | 类型、上下限、枚举、允许空值和时效要求 |
| 缺失行为 | `BLOCK`、`BASIC`、`SKIP` 或 `MANUAL` |
| 决策依赖 | 该指标控制的章节、结论或动作 |

## 2. 五级字段

| 字段等级 | 用途 | 缺失影响 |
|:---|:---|:---|
| `basic_required` | 生成有意义基础报告所需的事实和指标 | 阻断报告，输出基础数据缺口，不生成空壳报告 |
| `enhancement_global_required` | 把增强来源与基础事实安全合并所需的连接、范围和追溯信息 | `auto` 保留基础版；显式 `enhanced` 阻断 |
| `module_required` | 某个增强模块能够成立所需的最小指标集 | 只跳过该模块或将依赖动作标 `MANUAL` |
| `full_required` | 预先声明为完整增强清单的模块或指标 | 不影响已有部分增强；未全部满足时不标记完整增强 |
| `display_optional` | 只丰富展示、不控制版本和动作的字段 | 显示 `—` 或省略，不参与完整增强判定 |

`full_required` 是“完整增强清单”，不是所有带“选填”字样的展示字段。创建 Skill 时必须明确哪些模块进入该清单。

## 3. 数据有效性

字段同时满足以下条件才算有效：

1. 不是空值、占位符、错误码或被静默补成的 0。
2. 类型、枚举和数值范围正确。
3. 来源可追溯，且读取状态和时间可确认。
4. 数据时效满足来源表声明的 SLA。
5. 实体、站点、周期、币种、时区、归因、税口径、粒度及该领域其他口径一致。
6. 派生指标的分子、分母均有效，分母不为 0，计算公式可复核。

报告版本、数据质量 A/B/C/D、证据等级强/中/弱/冲突/无证据是三条独立轴。完整增强不自动等于数据质量 A，基础版也不自动等于弱证据。

## 4. 统一版本路由

报告型 Skill 默认使用逻辑参数 `report_edition=auto|basic|enhanced`。命令行 Skill 可映射为 `--report-edition`，对话型 Skill 也必须保留同样语义。

固定输出标签：

- `基础版报告`
- `增强版报告（部分增强）`
- `增强版报告（完整增强）`

按以下顺序判定，不得交换优先级：

1. 任一 `basic_required` 无效：不生成报告，输出基础数据缺口和补救方式。
2. 用户显式选择 `basic`：只生成基础版，不消费增强来源。
3. 输入出现凭证字段、损坏数据、非法状态或其他安全/契约错误：任何模式都阻断，错误信息不得回显敏感值。
4. 增强全局口径无效或没有任何模块完成：`auto` 输出基础版并记录原因；显式 `enhanced` 阻断。
5. 至少一个增强模块的全部 `module_required` 有效：输出部分增强。
6. 所有声明为 `full_required` 的模块和指标有效：输出完整增强。

伪代码：

```text
if basic_required_invalid:
    BLOCK_WITH_BASIC_GAPS
elif requested == basic:
    BASIC
elif security_or_contract_error:
    BLOCK
elif enhancement_global_invalid or complete_module_count == 0:
    BASIC_WITH_REASON if requested == auto else BLOCK
elif all_full_required_complete:
    FULL_ENHANCED
else:
    PARTIAL_ENHANCED
```

模块缺失只影响依赖它的章节和动作。可用模块继续输出；缺失模块标 `SKIP`，需要人工补数据才能判断的动作标 `MANUAL`。不得用单一总状态抹掉已经成功的模块。

## 5. 报告头与模块表

每份报告至少展示：

```markdown
# [报告名称]

- 报告版本：基础版报告 / 增强版报告（部分增强） / 增强版报告（完整增强）
- 版本原因：[命中哪些来源、指标和模块，或为什么降级]
- 数据质量：A / B / C / D
- 证据等级：[整体判断，并保留逐结论证据等级]
- 数据范围：[实体、站点、周期、币种、时区及领域口径]

## 数据来源
| 来源 | 角色 | 状态 | 读取时间 | 口径 | 限制 |

## 指标口径
| 指标 | 定义/公式 | 来源 | 单位/粒度 | 字段等级 | 状态 |

## 增强模块覆盖
| 模块 | 状态 | 已有指标 | 缺失指标 | 对结论/动作的影响 |
```

基础版仍需显示其实际来源和指标。部分增强必须展示模块覆盖表；完整增强也不能隐藏来源、口径和未验证项。

## 6. 创建器的提问与推导方式

不要把整份来源表和指标字典丢给用户填写。按以下顺序工作：

1. 先从用户需求、现有 Skill、数据文件列名、接口文档和业务模板推导候选来源与指标。
2. 区分已确认事实、合理候选和待验证信息。
3. 只补问会改变基础版、增强模块、完整增强清单或口径安全的高影响字段。
4. 把确认结果写入目标 Skill 的 `SKILL.md`；表格较长时放入目标 Skill 的 `references/report-editions.md`。

创建器只设计目标 Skill 未来如何调用 MCP/API。除非用户要求现场验证，不为了编写 Skill 消耗真实店铺查询。目标 Skill 每次真正运行报告时，才实时检查来源可用性、权限和数据回包。

## 7. 契约加按需脚本

每个报告型 Skill 都必须有上述契约，但不强制共享运行时：

- 仅人工输入、规则简单且无确定性计算：可把决策表直接写入 `SKILL.md`。
- 涉及自动取数、多个模块、指标计算、范围匹配或 CLI：在目标 Skill 内生成专用版本路由脚本和单元测试。
- 运行脚本至少测试基础版、部分增强、完整增强、`auto` 降级、显式增强阻断、凭证拒绝和缺失值不补 0。

## 8. Amazon 数据源边界

- 自己店铺的广告、订单、库存、财务、结算等私有经营事实，只能来自官方 API、已授权 MCP/ERP、团队可信服务或官方导出文件。
- 公开前台、竞品公开数据和第三方市场工具可以作为声明过的事实源或增强源，但不得冒充私有经营数据。
- 多个 ERP 或工具同时存在时，先选主来源；只有实体映射和全部口径验证一致后才能合并。
- Token、Secret、Cookie、授权头、AppID/AppSecret 和内部身份标识不得写入上下文文件、报告、日志或聊天。

## 9. 最小验收案例

报告型目标 Skill 至少具备以下回归：

1. 非报告型产物不进入版本问诊。
2. 只有基础数据时生成基础版并说明增强缺口。
3. 一个增强模块完成时生成部分增强，其他模块 `SKIP/MANUAL`。
4. 完整增强清单全部完成时生成完整增强。
5. 只缺 `display_optional` 时仍保持完整增强。
6. 口径冲突时 `auto` 保留基础版，显式 `enhanced` 阻断。
7. 基础必填缺失时输出缺口，不生成伪报告。
8. 凭证字段在任何模式下都拒绝且不回显值。
